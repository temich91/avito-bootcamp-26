# avito-bootcamp-26

## Решение

В качестве базового и единственного решения для задачи поиска релевантных объявлений по поисковому запросу используется BM25.
Поиск выполняется отдельно по заголовку и описанию объявления, после чего полученные оценки релевантности нормализуются и объединяются с заданными весами.

### Общая схема

Pipeline состоит из следующих этапов:

1. Загрузка обучающих данных.
2. Формирование `query_id` для каждого поискового запроса.
3. Разделение данных на train/validation по уникальным запросам.
4. Предобработка текстовых признаков.
5. Построение BM25-индекса по объявлениям.
6. Получение топ-50 кандидатов для каждого запроса.
7. Локальная оценка качества с помощью `Recall@50`.
8. Построение индекса на benchmark items.
9. Генерация предсказаний для benchmark queries.
10. Сохранение результатов в `answer.csv`.

Разделение на train и validation выполняется по уникальным `query_id`, а не по отдельным строкам.
Это позволяет избежать ситуации, когда один и тот же поисковый запрос одновременно присутствует в train и validation.

По умолчанию используется:

* `validation ratio = 0.15`
* `random seed = 42`

### Предобработка текста

Для обучающих данных используются:

* `search_query`
* `search_infm_params_text`
* `item_title_raw`
* `item_description_raw`

Для объявлений индексируются очищенные:

* `item_title_raw`
* `item_description_raw`

Для поискового запроса объединяются очищенный текст запроса и дополнительные параметры:

```text
clean_search_query + clean_search_infm_params_text
```

### BM25-индексация

Для заголовков и описаний создаются два независимых индекса `BM25Okapi`.

Для токенизации используется простое разделение текста по пробелам.

Индекс строится по уникальным `item_id`.

### Расчёт итоговой оценки

Для каждого запроса BM25 отдельно рассчитывает оценки релевантности по заголовкам и описаниям.
Поскольку распределения оценок двух индексов могут различаться, перед объединением они нормализуются методом Min-Max.

Если все значения оценки одинаковы, возвращается массив нулей.

После нормализации формируется итоговая оценка:

```text
final_score =
    0.8 * title_score +
    0.2 * description_score
```

Используемые веса:

* `title_weight = 0.8`
* `desc_weight = 0.2`

Совпадения в заголовке имеют больший вклад в итоговую оценку релевантности, чем совпадения в описании.


### Локальная валидация

Для validation-части формируется ground truth. Для каждого запроса сохраняется множество объявлений, которые считаются релевантными.:

```text
query_id -> set(item_id)
```

### Параметры решения

| Параметр           |  Значение |
| ------------------ | --------: |
| BM25 `k1`          |       1.5 |
| BM25 `b`           |      0.75 |
| Validation ratio   |      0.15 |
| Random seed        |        42 |
| Top-K              |        50 |
| Title weight       |       0.8 |
| Description weight |       0.2 |
| Retrieval metric   | Recall@50 |

## Запуск

Исходные .parquet файлы поместить в `avito-bootcamp-26/data`.

Установить зависимости:

`pip install -r requirements.txt`

Запустить `src/scripts/make_prediction.py`

Результат появится в `src/outputs/answer.csv`
